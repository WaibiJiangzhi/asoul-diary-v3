# Asoul一个魂生活日记 v3

一本为手机设计的温馨生活日记。它希望让记录变得足够简单：即使躺着，也能用很少的操作记下今天；每一次打勾和进度变化都有明确、舒服的反馈，也能慢慢看见自己的成长。

## 设计关键词

**A-SOUL 主题、温馨、日记、陪伴成长、反馈感强、手机端、操作简单、简洁。**

这些词是界面和功能取舍的共同标准：第一屏先呈现正在记录的内容，不用大段介绍占位置；装饰要像陪伴，而不能盖过记录；所有主要操作都应适合单手完成。

主题系统分为两层：整本日记可以选择嘉然粉、贝拉红、乃琳蓝，标题、按钮、选中状态、边框、浅色底和阴影会作为一套完整色阶同步变化；倒计时和进度卡还可以单独选择主题色，卡片内的日期、数字、进度条和按钮必须保持一致。

## 主要功能

- **今日**：在昨天、今天和明天之间切换；常用事项支持滚动、多选和批量添加，也可以手动写一件小事。事项与常用模板都可在手机上长按拖动排序，完成后会移到底部并折叠。每日事项只短暂保留，收进日记的快照才会长期保存。
- **成长**：保留横滑大卡体验。条形卡积累数量，一天可多次记录正负数、文字足迹，也可设置期望完成日期；圆环卡每天选择一种状态，支持 1–4 种自定义名称、颜色与表情，以日期或总览回看，并可给其中一种状态设置期待天数。圆环区分待记录与未来日期。两种卡共用日历补记和按日足迹，结束后可收入纪念册、恢复或再来一期。倒计时支持日子手记。
- **表情**：今日事项、常用事项和成长卡共用 Emoji 与姐仨表情选择器；单层横栏用代表图切换系列，保留最近使用。表情代号采用原始名称，例如 `[2026乃琳的酒馆_爱你]`。
- **日记**：按天收进今日事项、倒计时和进度记录，正文支持文字与表情混排、复制代号和粘贴还原；横线默认关闭，可在设置中开启。可加入最多 9 张本地照片，日历支持九种颜色的特殊日期标记。
- **主题与数据**：日记纸支持贝拉、嘉然、乃琳三套完整主题色；选择收藏壁纸后，内容会变成保持可读性的轻透层，让壁纸真正成为页面背景。数据保存在本机，支持完整备份、恢复和清空。

v3 使用独立的数据结构，不读取、不迁移 v2 数据。

## 当前阶段

当前版本进入阶段性收官和个人试用期：保持现有体验，优先记录真实使用中出现的问题，不主动扩展功能。正式发布前再统一处理版本号、数据迁移和发布检查。

## 项目结构

- `app/app`：页面入口与全局样式入口。
- `app/components/diary-app.tsx`：应用组合根，只连接页面、抽屉和全局反馈。
- `app/components/diary`：今日、成长、日记和设置的界面模块。
- `app/hooks`：自动保存、更新机制，以及今日、成长、日记等业务控制器。
- `app/lib`：本地数据、日期、类型、默认值与纯状态规则。
- `app/styles`：外壳和三个板块的独立样式。
- `app/lib/state.ts`：短期事项清理与日记内容判定等纯状态规则。
- `app/public`：PWA 图标、壁纸和动态表情等静态资源。
- `app/fixtures/two-years-sample-backup.json`：可直接从设置中恢复的两年压力测试备份，包含 730 篇日记、成长记录、日期标记和少量模拟照片。
- `本地素材（不上传）`：原始素材仓库，已由 `.gitignore` 排除，不会上传 GitHub。

最外层的 `app` 是当前 Cloudflare Pages 使用的网页工程根目录；里面的 `app/app` 是框架约定的页面目录，两者用途不同。若以后调整部署根目录，可以再把网页工程整体提到仓库根目录；当前先保持线上构建路径稳定。

## 本地运行

双击项目根目录的 `启动v3.cmd`即可构建并打开本地网页。开发时也可以在 `app` 目录执行 `npm run dev`。

阶段性整理或准备提交前，在 `app` 目录执行 `npm run check`，会依次完成类型检查、代码检查和正式构建。

需要重新生成两年模拟数据时，在 `app` 目录执行 `npm run fixture:two-years`。
把新的 JPG/PNG 放进壁纸目录后，执行 `npm run wallpapers:optimize` 会转换为 WebP 并移除原文件。

姐仨表情的原件保存在 `本地素材（不上传）/姐仨表情包合集`，按成员目录和系列编号整理。执行 `npm run stickers:import` 会生成网页资源与表情目录；静态图片转为 WebP，动态 GIF 保留，横栏封面使用静态图。它保留原始素材，不会上传原件。

执行 `npm run test:records` 可检查每日状态、日期统计、累计补记、备份与表情代号规则。

## 发布更新

正式构建会自动给 Service Worker 写入本次发布标识。新版会先在后台准备好，再用底部提示和设置键小圆点提醒；用户确认后刷新，若暂不确认，则会在关闭所有旧页面后自然切换。构建更新不会主动清除本地日记。

应用外壳与壁纸使用独立缓存。普通代码更新不需要手工调整缓存号；只有用新图片替换了同名壁纸时，才需要更新 `app/lib/defaults.ts` 中的 `WALLPAPER_ASSET_VERSION`，让手机重新下载这批壁纸。

更短的职责边界见 `docs/architecture.md`；给后续 Codex 任务的稳定约定见根目录 `AGENTS.md`。
