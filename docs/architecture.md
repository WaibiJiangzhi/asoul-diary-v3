# V3.0 架构

## 界面与职责

- `components/diary-app.tsx` 连接「生活 / 纪念册」、单一操作面板、设置与全局反馈；页面保持各自滚动位置。
- `components/diary/life-*.tsx` 实现卡片列表、配置、记录和详情；`Sheet` 统一底部面板。
- `hooks/use-life-controller.ts` 处理创建、记录、排序、归档与恢复；`use-diary-state.ts` 处理加载、自动保存、跨日刷新和主题。
- `lib/types.ts` 定义结构，`lib/life.ts` 放纯规则，`lib/card-edit.ts` 验证配置编辑并保留最新记录，`lib/db.ts` 负责 IndexedDB。
- `hooks/use-photo-urls.ts` 管理照片 URL 的加载与释放；示例图片通过独立的上下文提供，不读取真实照片库。
- `lib/card-templates.ts` 提供常用卡片默认项与重开规则；常用清单独立保存在本地并随备份导出，修改不联动已添加的生活卡。纪念册可再开一期。
- `styles/shell.css` 保留外壳与设置，`styles/life.css` 负责生活卡片；表情、编辑器有独立样式。

## 数据模型

`AppState → cards / commonCards / companions / settings`。四种卡共用 `LifeCard.records`，差异只在配置和展示。

记录带日期、文字、照片 ID，可附数量增量、每日状态或阶段变化。状态使用稳定 ID；一天只留一个状态，替换或取消时保留文字与照片。阶段按记录日期和创建时间计算当前状态，补记旧日期不会覆盖后来的变化。

切换卡片类型保留原配置与记录。累计值和达成状态始终由记录计算：撤回后重算，再次达成再次庆祝。记录卡达成期待或填满整个周期都能庆祝，两者含义不同。

卡片的 `location` 为 active、later 或 memory。归档不复制记录，不自动发生；恢复保留内容，开启新一期才创建空记录的新卡片。任何内容都不因跨天自动过期。

记录卡用开始日期与记录周期计算期待日期，进度卡使用 `progress.expectedDate`，阶段与随记使用 `expectedDate`。期待日期不限制后续记录或配置编辑；仍禁止记录未来和开始前的日期。新一期清空具体截止日期。

陪伴卡在首次进入和跨日时按「当天、明天、其他」优先级随机选择，同一天切换页面不重新随机。首页轻提醒汇总当天与明天的期待，超过五张陪伴卡时导航改用页码。

近期记录与阶段状态通过单次遍历寻找，不反复复制排序；圆环和日历按日期索引状态，历史记录每批显示 30 条。

## 保存、照片与备份

使用独立的 `asoul-life-v3-preview` 数据库，备份标识为 `asoul-life-v3`；旧版数据原样留在原数据库。

状态串行保存，失败会重试；修订标记防止另一个旧页面覆盖新内容。恢复前验证结构、引用和照片，再在同一事务中替换。照片批量加入，删除 Blob 与移除记录引用一起提交，保存失败不损坏已存照片。

照片存为 Blob，备份时转为 Base64。正文仍是纯文本，表情存原始代号；编辑器只呈现受信任目录图片，不存外部 HTML。最近使用表情属于设备偏好，可自行管理。

`/preview` 使用相同界面和规则，但状态仅在内存中；照片写入、恢复和清空被禁用。静态示例插画位于 `public/examples`，生成的示例备份包含这些插画，导入后可正常导出。它不用于替换本机记录。

备份提醒从设备首次发现记录时计时，每 30 天显示一次轻提示，确认后重新计时。时间戳存 localStorage；写入失败时保留本次会话的确认状态。该提醒不自动备份、不申请通知权限，示例页不计时。

## 构建与反馈

保留 Pages 静态输出及 Workers 构建。Service Worker 缓存构建脚本和样式，错误导航不覆盖离线首页；更新前先保存。

`outputs`、`work`、`dist`、`.wrangler` 不参与 TypeScript 检查，源码快照和临时复核产物不会被误当成应用源文件。大数据备份恢复测试使用独立的 fake-indexeddb，不操作用户数据库。

普通记录共用轻柔音效，达成共用庆祝音效。圆环切换保持布局，顺时针展开；遵循系统减少动态效果偏好。手机输入法、振动和扬声器效果仍需在具体设备上体验。

只为真实需要增加抽象，不预建原生 App 或远端同步层。
