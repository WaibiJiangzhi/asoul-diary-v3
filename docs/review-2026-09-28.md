# 网页版检查报告 · 2026-09-28

本轮检查数据、记录输入、每日与分组、纪念册、PWA 和构建。只修改网页版源码，未发布网站、未重新打包 APK；没有读取或替换用户正式生活页的数据。浏览器交互使用独立 `/preview` 标签，存储回归使用独立 fake-indexeddb。

## 已修复

| 问题 | 处理 |
| --- | --- |
| 提交记录时仍可修改正文、状态和照片，后改的内容可能不在本次保存内 | 保存期间锁住输入和工具栏、防止重复提交；保存成功后才显示成功提示，失败时仍保留草稿 |
| 恢复同编号照片后，旧的 Blob URL 可能继续显示 | 照片预览跟随数据替换代数重新加载，释放旧 URL；照片 ID 列表改用 JSON 编码，避免分隔符冲突 |
| 异步确认一点击就关闭，恢复备份时可继续操作其他内容 | 确认框保留处理状态直到完成，期间禁止重复确认和取消 |
| 纪念册当前月份的最后一张卡回到生活后，筛选仍停在已不存在月份 | 自动使用有效月份；同一天按真实收录时间排序；搜索去首尾空格并忽略大小写 |
| 只写文字或添加照片、没有选状态时，七天栏仍标为未记录 | 显示小笔图标，辅助文字为“已写记录，未选状态”，与每日完成状态一致 |
| 备份时间戳只检查字符串类型，无效日期可进入纪念册 | 在替换前拒绝不可解析的卡片／记录时间戳，保留原数据 |
| 安装提示被取消后仍复用已消费的浏览器事件 | 一次使用后清除；不可用时提示浏览器菜单安装路径 |

纪念册的纯筛选规则整理到 `app/lib/memories.ts`，界面共用同一结果。没有改动已有卡片布局和数据格式版本。

## 验证结果

- `npm run check`：类型检查、代码检查、Workers 构建通过。
- `npm run build:pages`：静态构建及页面预渲染通过。
- `npm run test:records`：25 项业务规则 + 4 项表情／正文测试通过。
- `npm run test:storage`：11 项存储 + 3 项 Service Worker 测试通过。
- 大数据备份：120 张卡、15,936 条记录、1,152 张照片完整导入再导出；包括卡片状态、记录和图片内容比对。
- 异常恢复、事务失败、两个页面保存冲突、照片删除事务、草稿与图片恢复均有回归覆盖；新增同 ID 照片替换、每日记录撤回和纪念册有效月份测试。
- 浏览器实测：关闭再打开恢复草稿；文字加表情，从表情盘直接确认；完成后每日卡片仍保留；运动分组与每日叠加、进度卡加入每日、快捷加数量后更新状态；切换生活／纪念册保留筛选；纪念卡恢复后失效月份回到全部。
- 390 px 手机宽度检查生活页、记录面板；320 px 检查纪念册，未出现页面横向溢出。复核标签未发现控制台 error。

## 仍需单独验证

- 桌面手机尺寸模拟不能替代 Android／iOS 真机输入法、返回手势、相册、后台进程回收和安装后离线体验。继续试用时优先验证这些项目。
- 本地数据仍随设备和浏览器保存，没有跨设备同步；关闭前未确认的草稿不包含在完整备份中。
- `npm audit --omit=dev` 本次报告为 0 条已知告警，不等于独立安全审计。完整 audit 有 3 条 moderate，来自开发工具 `@capacitor/cli → xcode → uuid`；自动修复建议涉及 Capacitor CLI 版本调整，本轮保留工具链，后续更新 APK 前单独处理和构建验证。
- Pages 构建提示一个约 500 kB 的未压缩 JS 块。未为消除提示而盲目拆包；低端手机与弱网首开速度仍需实测。

本轮结果适合作为小范围试用前的技术检查依据，不代表已覆盖所有手机浏览器，也不代替正式上线后的实际设备反馈。
